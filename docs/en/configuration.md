# Configuration

[Documentation index](README.md) · [简体中文](../zh-CN/configuration.md)

The installer writes deployment settings to `/opt/crewqual/.env`. Application settings are stored in the database, with sensitive values encrypted using `SETTINGS_ENCRYPTION_KEY`. Distinguish host deployment parameters from settings administrators can change in the application. Recreate affected containers after changing their environment; restarting alone does not load updated Compose environment values.

## Network and secrets

| Setting                                         | Meaning and constraints                                                                                                                 |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `SERVICE_MODE`                                  | Production uses `remote`; `mock` is rejected.                                                                                           |
| `APP_ORIGIN`                                    | The browser-facing origin, including scheme and any non-default port, without a path or trailing slash. It must match the network mode. |
| `DEPLOYMENT_NETWORK_MODE`                       | `lan`, `http`, or `tls`. LAN HTTP origins must use localhost, 127.0.0.1, or a supported private IPv4 address.                           |
| `APP_PORT`, `APP_BIND`                          | Application port and host bind address. Configure through the installer or domain script.                                               |
| `APP_DOMAIN`, `TLS_EMAIL`, `CADDY_SITE_ADDRESS` | Caddy domain and certificate settings. Custom certificates also use generated Caddy TLS settings and files in `tls/`.                   |
| `NETWORK_ACCESS_SECRET`                         | Network access secret shared between the proxy and application, generated by the installer.                                             |
| `SETUP_AUTH_CODE_HASH`                          | SHA-256 hash of the one-time setup code, not the code itself.                                                                           |
| `SESSION_SECRET`                                | Explicitly required in `remote` mode; at least 48 characters in production.                                                             |
| `SETTINGS_ENCRYPTION_KEY`                       | At least 32 characters in production and different from `SESSION_SECRET`. Preserve its value to decrypt existing sensitive settings.    |
| `READINESS_PROBE_SECRET`                        | At least 32 characters in production, used by internal container readiness probes.                                                      |
| `TRUSTED_PROXY_HOPS`                            | Must be explicit in production. Shipped Compose files default to `1` behind Caddy. Recheck when changing proxy layers.                  |
| `PILOT_SESSION_TTL_MINUTES`                     | Member session duration, default 60 minutes.                                                                                            |
| `ADMIN_SESSION_TTL_HOURS`                       | Administrator session duration, default 8 hours.                                                                                        |

The installer generates secrets. When preparing an environment manually, run `openssl rand -hex 48` and `openssl rand -hex 32` separately for independent values. Keep `.env`, setup codes, and TOTP secrets out of version control.

## Database and storage

`POSTGRES_PASSWORD` belongs to the database owner/migration role. `POSTGRES_APP_PASSWORD` belongs to the runtime role, `crewqual_app`. `DATABASE_URL` uses the runtime role; `DIRECT_URL` uses the migration role. Shipped Compose files provide owner connection details only to the migration service. Keep the runtime connection on its dedicated role.

| Setting                                    | Meaning                                                                                                                                                |
| ------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `STORAGE_MODE`                             | Release installations default to `builtin`; source Compose defaults to `external`.                                                                     |
| `S3_ENDPOINT`                              | Production requires HTTPS. The built-in exception is `http://minio:9000` with `STORAGE_MODE=builtin`.                                                  |
| `S3_BUCKET`, `S3_REGION`                   | Private bucket and region; defaults are `crewqual-private` and `us-east-1`.                                                                            |
| `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY` | Storage credentials. The production secret must have at least 16 characters and cannot use the built-in example value.                                 |
| `S3_FORCE_PATH_STYLE`                      | `true` or `false`, according to the storage service. Built-in MinIO in release deployments defaults to `true`.                                         |
| `S3_SSE_KMS_KEY_ID`                        | Optional KMS key identifier.                                                                                                                           |
| `OUTBOUND_ALLOWED_HOSTS`                   | Comma-separated hosts or `host:port` entries. External S3 and remote backup hosts require explicit entries even when they resolve to public addresses. |
| `OUTBOUND_ALLOWED_CIDRS`                   | Additional private network CIDRs that may be accessed.                                                                                                 |

The deployment operator controls outbound allowlists. Application administrators cannot expand them in settings. Before changing storage or backup destinations, check both the hostname and resolved network addresses against this boundary.

## Notifications and recognition

| Feature           | Settings                                                                                                                                                   |
| ----------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SMS               | `SMS_ADAPTER=disabled` or `webhook`. Webhook mode needs `SMS_WEBHOOK_URL`; set `SMS_WEBHOOK_AUTH_TOKEN` as required by the gateway. `fake` is for testing. |
| SMS receipts      | Use a separate `SMS_RECEIPT_WEBHOOK_SECRET`.                                                                                                               |
| Feishu            | `FEISHU_ADAPTER=disabled` or `webhook`, with `FEISHU_WEBHOOK_URL` and an optional authentication token.                                                    |
| Image recognition | `VLM_ADAPTER=disabled` or `qwen`, with `QWEN_BASE_URL` and `QWEN_MODEL`.                                                                                   |

The default Qwen model name is `Qwen3.7-35B`. Setting a model URL does not start a model server. Deploy a working service separately and configure outbound access for it.

Keep `DEV_ENDPOINTS=false` in production. `CREWQUAL_ACCEPTANCE_EXTERNALS_DISABLED` and `ACCEPTANCE_ENVIRONMENT_ID` are for isolated acceptance environments, not live deployments.

## Bootstrap and updater

Leave `INITIAL_ADMIN_EMAIL`, `INITIAL_ADMIN_PASSWORD`, and `INITIAL_ADMIN_TOTP_SECRET` empty to create the first super administrator at `/setup`. Headless bootstrap requires all three together. See `.env.example` and the bootstrap configuration for initial organization, unit, and job-template values.

Regular Linux uses the host updater with `CREWQUAL_UPDATER_MODE=managed`; WSL2 uses `manual`. The installer manages image digests, updater shared secrets, and its backup key. The example image digests in `.env.example` are placeholders.

Before configuration changes, keep copies of `.env` and relevant certificates. See [operations](operations.md) for the persistent data needed during upgrades and recovery.
