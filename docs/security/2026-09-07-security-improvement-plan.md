# CrewQual 安全改进实施计划

日期：2026-09-07。状态：核心认证与浏览器防护已实施，部署验收仍待完成。本文件不代表整体整改或验收已完成。

依据：`2026-09-07-product-security-gap-audit.md`；审计代码基线 `782a1d18c74ec26e4c1cae4a65d9e52c1b86c036`。实施前按最新工作树复核差距，保留其他任务进行中的发布与恢复流程改动。

## 1. 目标与范围

- 补齐产品范围内 ASVS 5.0.0 L2（含适用 L1）及等保二级工程差距，增加已确认的九组 L3 能力。默认便捷认证、显式降级配置保留对应认证差异，不能标为全部通过。
- 范围包括产品代码、API、界面、数据库迁移、随附工具、测试和产品安全文档；不列部署方责任和不适用条目。
- 两套标准分别映射。跨标准无法兼容时 ASVS 优先，记录等保差异；例如不强制周期性密码到期，泄露和本人主动更换另行处理。
- 小目标若会被更高等级方案替换或大幅重做，直接采用已确认的高等级方案。标准条款、工程目标、配置状态、验收结果分别记录。
- 新增界面保持现有中文/英文支持。所有模式、风险和采购说明描述实际能力，不使用“选中即符合标准”“已认证”等标签。

## 2. 已锁定的产品行为

### 2.1 初始化与后台共用三档认证策略

| 档位                   | 管理员                                 | 成员                                                 | 展示说明                                                   |
| ---------------------- | -------------------------------------- | ---------------------------------------------------- | ---------------------------------------------------------- |
| 增强认证               | 密码＋动态密码＋FIDO2 实体硬件安全钥匙 | 工号定位账号，密码＋动态密码＋FIDO2 实体硬件安全钥匙 | 面向 ASVS L3／等保三级身份鉴别要求；需额外采购硬件安全钥匙 |
| 组合认证               | 密码＋TOTP 动态密码                    | 工号定位账号，密码＋TOTP 动态密码                    | 面向 ASVS L2／等保三级身份鉴别要求；需绑定验证器应用       |
| 便捷认证（新安装默认） | 密码＋TOTP 动态密码                    | 工号＋短信一次性链接                                 | 成员使用单因素认证，保留明确差异                           |

- 增强档的 FIDO2 注册和认证共同满足强度要求；当前实现只接受不可同步的单设备凭据，凭据撤销/遗失恢复仍需受控恢复流程和实物证据，不把通用 WebAuthn 支持、软件认证器或任意同步通行密钥自动当成硬件保证。
- 首批实物兼容验证使用 Yubico Security Key C NFC。采用标准 WebAuthn 接入，不引入微软 Entra 账号依赖；使用维护中的标准验证库，不自行实现密码协议。
- 验证可信 origin、RP ID、一次性 challenge、用户主动确认、硬件认证器证据与凭据状态。生产增强档需要安全上下文；不满足时阻止启用并明确原因。
- 增强档不提供短信登录、TOTP 单独回退或旧单因素管理员入口。短信可以用于通知。
- 工号是账号标识，不增加姓名中间字、安全问题或知识问答认证。
- 超管可关闭管理员 TOTP、调整成员认证方式。与预设不一致时标为“自定义／已降级”，不能保留增强档的配置状态。
- 高敏业务操作的额外验证默认开启：普通档使用 TOTP；增强档使用 FIDO2，再有 TOTP 时可额外校验。该开关可以关闭，但凭据、手机号、MFA 和策略变更所需的当前完整再次认证不能关闭。
- 高敏操作范围包括创建超管、提权、发起他人凭据恢复、修改备份目标、关键集成凭据和软件升级操作。再次认证证明绑定本人、会话、动作和目标，有效期最多 5 分钟且单次消费。
- 降级前验证当前完整认证组合、显著确认、记录审计并通知受影响用户；策略变化撤销受影响的旧业务会话。

初始化便捷档提示：

> 成员将使用单因素登录，不满足 ASVS L2／等保三级的组合认证要求。其他安全措施仍然有效。

关闭附加因素提示：

> 关闭后将使用单因素登录，不满足 ASVS L2／等保三级的组合认证要求。其他安全措施仍然有效。

所有档位公共说明：

> 本选项仅配置身份认证措施，整体符合性需完成其他适用要求及验收。

关闭高敏操作额外验证时使用该操作对应的警告，不误称所有登录均变为单因素。界面同时显示有效认证策略、未完成绑定人数和验收状态。

### 2.2 成员保护和凭据生命周期

- 保留本人资质查看、上传、更新申请；不能修改审核结论、角色或单位。所有新旧 API、字段、对象下载与签名 URL 均在服务端校验归属。
- 短信请求统一返回“若信息匹配，登录链接将发送至预留手机号”。覆盖未知、停用、冷却等情况，避免通过响应内容或明显时序差异暴露人员记录。
- 按账号、预留号码和可信来源地址限流，发送冷却默认 60 秒；复用现有限流基础设施，发送队列重试同样受预算和幂等约束，不信任任意转发 IP 头。
- 链接使用高熵随机令牌，数据库只保存摘要；默认及最大有效期均为 10 分钟。兑换原子执行、一次成功，与生成时认证事务及策略版本绑定。
- 请求日志、审计、异常和分析系统不记录原始登录令牌。短信发送仅在必要投递链路处理链接，不将完整短信正文作为普通日志。
- 新策略禁用短信后，已发送链接、重置邀请和排队任务不能获得旧权限；号码变更后旧目标和旧令牌失效。
- 本人自行设置、修改密码；管理员只能发起恢复，不能指定或读取最终密码。密码统一使用现有 Argon2id，新设密码统一校验常见、泄露、上下文弱口令。
- 改密、换号、重绑因素走独立的完整再次认证或身份核验流程；短信不能独自恢复强认证账号并取得完整权限。不引入安全问题。
- 初次绑定、因素恢复和业务登录分别建模。绑定/恢复凭证只允许完成指定流程，不能访问业务 API；保留操作依据和核验记录。
- 修复 TOTP 生成器：从至少 20 字节随机数据正确 Base32 编码，实际校验密钥达到要求；有效接受窗口不超过 30 秒，原子防重放。旧 96 位密钥重新绑定，不通过补零伪装升级。
- 管理员和成员都有自助退出、本人会话查看与撤销；撤销需要再次验证，不能撤销他人会话。同一浏览器重新登录使旧 token 失效，不强制踢掉其他设备。
- 空闲超时与绝对 TTL 分开。新默认空闲超时管理员 15 分钟、成员 30 分钟；保留绝对上限并通过风险文档说明。后台轮询不能自动永久续期。

### 2.3 安全审计与公网风险统计

- 设置增加“安全审计”标签页，支持时间、人员、事件、结果筛选和详情。原始事件只追加；权限允许的会话撤销是独立账号操作，单独鉴权并记录审计。
- 独立授予审计读取能力，不同时授予账号、系统或安全策略修改权。公网风险统计只读，不增加处理状态；账号和会话操作继续检查各自权限。
- 覆盖登录成功/失败/未知账号/限流、授权拒绝、CSRF、安全校验、异常、策略与凭据变化；补 L3 成功授权和敏感证照读取元数据。
- 日志结构化、脱敏、有关联 ID；不保存密码、OTP、原始令牌、完整手机号、图片或签名 URL。日志入口和 CSP 报告限流，避免日志耗尽存储。
- 公网风险能力按 [2026-09-08 公网风险统计与访问边界实施计划](./2026-09-08-security-monitoring-access-control-plan.md) 实施：统计扫描、撞库和分布式登录尝试，在安全审计页展示分类、数量和趋势。
- 不根据陌生地址生成登录告警。飞行员和船员经常跨地区及网络工作，地址变化本身不能作为异常结论。
- 所有具备 `audit.read` 的管理员查看全局态势；普通管理员只能查看本单位完整账号，其他单位账号脱敏。
- 每次管理员登录后显示从上次成功登录开始、最长 30 天的统计摘要；首次登录显示最近 24 小时。摘要没有服务端已读或处置状态。
- 第一版不发送短信、邮件或飞书安全通知，也不因统计结果增加自动封禁。现有限流、锁定和多因素认证继续执行阻断。
- 抗钓鱼码及面向受影响用户的外部安全通知不在本轮风险统计范围内；未另行实现和验证前不能标为已支持。

### 2.4 浏览器、文件和密钥保护

- CSP 直接采用逐响应 nonce 方案，补 `base-uri 'none'`、可信资源限制、CSP 报告和 COOP；生产脚本移除 `unsafe-inline`，验证 SSR、hydration、缓存和窗口交互。
- 安全上下文使用满足属性要求的 `__Host-` 会话 Cookie，兼容清理旧名；HTTP 配置不冒充满足 Cookie 安全条款。
- 文件链路限制读取体积、格式和像素尺寸，服务端完整解码后重新编码，只保存并提供系统生成的私有图像。ASVS v5.0.0-V5.4.3 采用项目特定的“不适用”判断，但只有上传/导入/对象写入/备份恢复/下载清单、现有对象重建及恢复门禁全部通过后才能记为“不适用”；不增加杀毒扫描或隔离队列。
- 原子执行单用户持有总数/容量、并发、每日和短时上传配额；计入待关联、孤儿文件与预留容量，验证失败释放、删除和清理的一致性。迁移前统计现有占用，既有超额资料不自动删除。
- 手机号等默认在 API 最小化返回、界面脱敏；显式按需查看再次校验权限并记录读取，编辑场景单独授权。
- 增加设置根密钥版本管理、旧数据重加密与中断续跑；覆盖保留的 TOTP、集成、备份凭据及抗钓鱼短语。旧备份所需密钥不提前销毁，迁移失败可恢复。

## 3. 技术变更与迁移顺序

### 阶段一：策略和数据基础

1. 在现有 Next.js/Prisma/PostgreSQL 体系中增加统一认证策略解析；初始化、后台、所有登录/恢复入口和守卫共用，不复制开关判断。
2. 策略接口包含预设档位、有效管理员/成员认证方式、高敏挑战开关、策略版本、空闲超时；配置状态和验收结果使用独立类型。
3. 增加成员密码/TOTP 凭据、WebAuthn 公钥凭据、挑战与绑定/恢复状态；管理员不再要求在非 TOTP 模式下填入虚假 TOTP 秘密。
4. 会话绑定主体、认证因素证明、策略/凭据版本；加入受限绑定会话。审计事件保持不可变追加；公网风险统计不增加已读或处理状态。
5. 先修复当前完整再次认证、TOTP 密钥/窗口和基础安全日志；为后续迁移提供可靠保护。

### 阶段二：三档登录与账号迁移

1. 完成组合档、便捷档及成员自助凭据/会话；再接入 FIDO2 增强档和首次管理员安全钥匙注册。
2. 初始化超管必须完成所选档位验证才能结束初始化。新成员未绑定时仅获得受限开通权限。
3. 既有安装迁移保留实际策略，不自动强制新增因素或静默降级。旧 TOTP_ONLY 标为需整改的历史自定义状态，不继续作为新预设提供。
4. 切换强档前先完成操作者和至少一个可用超管的绑定与恢复准备；展示其他账号就绪情况。切换后未就绪账号只能走绑定或恢复，禁止旧 SMS 完整会话回退。
5. 策略版本更新、会话撤销及旧令牌失效协调提交；后台任务发送前重新检查版本。回滚产品版本也不得隐式恢复弱入口。

### 阶段三：审计和纵深保护

1. 完成安全审计权限及公网扫描、撞库和分布式登录尝试的统计与趋势；不增加已读或处置流程。
2. 完成 CSP/Cookie、文件重建及其适用性证据、配额、按需揭示、根密钥轮换与迁移工具。
3. 为配置修改、故障和安全降级输出可诊断的状态；不设置“开关全开就通过”的计算逻辑。

### 阶段四：条款验收与交付

1. 对原报告 A2-01～A2-15、G2-01/G2-02 和新增 A3-01～A3-09 逐条建立目标、代码证据、配置、测试及剩余差异矩阵；同一实现复用跨标准映射。
2. 完成 G2-V1/V2、V-01～V-06 的验证，包括仅保留产品备份及恢复材料时的恢复测试、全接口越权矩阵、上传并发、锁定恢复、依赖现状和安全设计证据。验证失败转为修复任务。
3. 验证 V-07～V-10 的 L3 证据，包括导出、保留删除、解析一致性、密码与外部资源控制、权限撤销一致性。数据历史保留未定义前不自动删除业务记录，对应条款不得标为通过。
4. 等保三级 G3-01 组合身份鉴别按档位映射。G3-02 使用现有身份、角色、权限、组织、单位和资源所有者作为主体/客体安全标记；不增加通用密级字段，按 2026-09-08 计划统一规则并完成新旧入口负向矩阵后再判断是否关闭差距。
5. 固定版本更新漏洞扫描证据、修复期限政策和条款映射；不把历史 CVE 或既有单测全绿当作当前合格证明。

## 4. 测试与完成条件

- 单元测试：策略矩阵、完整再次认证、TOTP 实际密钥/有效窗口、防重放、状态迁移、脱敏、权限和超时边界。
- PostgreSQL 集成测试：短信并发兑换仅一次成功、上传原子配额、策略切换与登录竞争、审计不可篡改、密钥轮换中断恢复。
- 浏览器测试：三档初始化和两类账号登录、绑定/遗失恢复、退出、同浏览器重登录、空闲超时、成员更新证照、公网风险统计与登录摘要、CSP 渲染。
- 负向矩阵：两个组织、所有角色、本人/他人资源及字段、新旧兼容 API；无因素证明、过期证明、降级及旧链接均不能越权。
- 故障测试：短信重试、风险采集或聚合不可用、数据库事务失败和部分迁移，均不偷偷放开认证或读取权限；统计不完整时不得显示零风险结论。
- WebAuthn 自动化使用虚拟认证器验证协议和流程；硬件性质与 USB-C/NFC 操作另用实物验证，无实物证据时该项明确待验证。
- 主动测试使用隔离 PostgreSQL/对象存储与合成数据，通知和模型使用替身；真实硬件验收单独执行，不向真实成员发测试消息。
- 执行仓库常规格式、lint、类型、单元测试及构建检查；增加上述定向集成/E2E。每阶段独立审查认证、迁移、并发和权限，再修复与复验。
- 交付物：实现与迁移脚本、三档使用及恢复说明、条款矩阵、自动化与实物测试证据、逐配置差异清单。
- 完成以实际行为、迁移可用及证据为准。便捷/降级模式保留已接受差异；增强模式仍须满足其他适用条款，才可讨论对应范围的完整 L3 验收结论。
