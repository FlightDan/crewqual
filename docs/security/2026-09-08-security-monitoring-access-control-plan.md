# CrewQual 公网风险统计与访问边界实施计划

日期：2026-09-08

状态：核心实现完成；发布环境验收仍有待验证项

关联文件：`2026-09-07-product-security-gap-audit.md`、`2026-09-07-security-improvement-plan.md`

## 1. 目标

本轮完成两项工作：

1. 统计公网入口的自动化扫描、撞库和分布式登录尝试，在安全审计界面展示分类、数量和趋势，并在管理员每次登录后显示一条简短摘要。
2. 把现有身份、角色、权限、组织、单位和资源归属整理为统一的主体/客体访问规则，补齐不一致的入口和跨边界负向测试。

本轮不按登录地址判断人员是否异常。飞行员和船员经常跨地区、跨网络工作，来源变化不能单独作为风险结论。系统不维护“陌生地址”列表，也不因地址变化阻止登录。

风险统计没有未读、已读、确认或处置状态，不发送短信、邮件、飞书等外部通知。现有登录限流、账号锁定和多因素认证继续负责阻断；统计功能只报告观察到的模式。

## 2. 已确认的产品行为

### 2.1 统计范围

- 覆盖进入 CrewQual Caddy 站点处理链的公网 HTTP 请求，包括已被公网访问策略拒绝的请求、常见探测路径、无效页面、无效 API 和无效方法。TLS 握手、ACME 挑战及 Caddy 自动 HTTP→HTTPS 重定向不进入应用风险统计，界面不得把这部分范围表述为已采集。
- 覆盖管理员与成员认证入口的失败、未知账号尝试和限流拒绝。
- 覆盖管理 API 的认证、权限和 CSRF 拒绝，但不把一次正常的权限不足直接称为攻击。
- 扫描和撞库统计同时包含管理员与成员入口。
- 成功登录不参与“陌生地址”判断。只有“已命中扫描或撞库规则的来源随后成功登录”可以作为规则组合证据，文案仍使用“疑似”，不能写成“确认入侵”。
- 查询参数、Cookie、密码、动态验证码、FIDO 响应、访问链接和密码重置令牌不得进入信号、日志或统计维度。

### 2.2 展示方式

- 所有具备 `audit.read` 权限的管理员均可查看全局统计。当前四种内置管理员角色都具备该权限。
- 安全审计界面提供 24 小时、7 天、30 天三个时间范围，展示疑似攻击批次、请求数、来源数和分类趋势。
- 每个管理员成功登录后显示一次摘要。时间范围从该管理员上一次成功登录开始，最长回溯 30 天；首次登录显示最近 24 小时。
- 登录摘要同时给出批次数、请求数和来源数。例如：“自上次登录以来识别到 3 组疑似扫描，共 147 次请求，来自 12 个来源。”零结果也明确显示。
- 登录摘要不写入服务端已读状态。前端只按当前会话 ID 避免同一次登录期间重复弹出。
- 全体管理员可以看到全局来源、分类和趋势。普通管理员查看本单位账号时可见完整标识，其他单位账号只显示脱敏标识和数量；超级管理员可查看完整关联账号。
- “相关请求”按所有命中批次的基础信号并集计算，同一请求即使命中多个规则或重叠窗口也只计一次；“来源”按该并集去重。同一基础信号可以进入多个分类，因此分类数允许重叠，界面不得把分类值直接相加冒充全局总数。

### 2.3 主体和客体

CrewQual 不增加“秘密、机密、绝密”等通用分级，也不建设独立的强制访问控制系统。安全标记来自现有业务关系，并由服务端可信数据生成。

| 类型           | 安全标记                                             | 访问规则                                               |
| -------------- | ---------------------------------------------------- | ------------------------------------------------------ |
| 超级管理员主体 | 管理员 ID、有效会话、`SUPER_ADMIN` 角色、权限        | 可跨组织和单位访问，但每项操作仍需对应权限             |
| 普通管理员主体 | 管理员 ID、有效会话、角色、权限、组织和单位          | 同时满足操作权限及单位范围                             |
| 成员主体       | 当前会话的成员 ID，以及服务端解析的人员、组织和单位  | 只能访问本人资源                                       |
| 后台任务主体   | 固定任务类型、可信队列负载和执行时重新读取的资源关系 | 只能处理任务指向且仍有效的资源                         |
| 人员与资质客体 | 人员/成员所有者、组织、单位、资源类型                | 按本人或管理范围访问                                   |
| 证照及识别客体 | 图片所有者、关联人员、关联申请或资质记录             | 所有者与父资源必须一致后才可读取、签发 URL 或送入识别  |
| 系统级客体     | 设置类别和权限代码                                   | 由专门权限控制；全局风险统计是 `audit.read` 的明确例外 |

页面只是数据的展示入口。真正需要控制的是人员、资质记录、证照图片、申请、通知、审计、设置和后台任务等服务端对象。

### 2.4 文件处理适用性

ASVS v5.0.0-V5.4.3 拟按本项目文件下载链路的适用性判断记为不适用，理由如下：

- 上传端只接受受限大小和像素尺寸的 JPEG。
- 服务端使用 `sharp` 完整解码，再生成新的 JPEG。
- 原始文件、原始元数据、注释和尾随载荷不进入对象存储。
- 用户取得的是私有存储中的系统生成图像，不是未经处理的外部文件。

这不是 ASVS 的通用豁免。只有以下证据门禁全部通过，审计矩阵才能把本项目的 V5.4.3 状态改为“不适用”：

- 机器清单覆盖所有上传、导入、对象写入、备份恢复和下载入口。当前盘点中，`POST /api/evidence-images` 是唯一接收最终用户二进制证照的入口；CSV 导入只解析结构化数据且不保存为可下载文件，产品备份是系统生成的加密产物。新增入口若未登记，测试失败。
- 每条最终用户文件写入路径都必须先完整解码，再由服务端编码为新的 JPEG；对象存储 helper 不能成为绕过入口。图库 AVIF 优化只能读取已经满足该来源证明的对象。
- 为现有 `EvidenceImage` 和对象存储建立来源版本。上线前逐个校验或重新解码、编码并原子切换对象；无法解码、数据库与对象不一致或缺少可信来源的对象默认不可下载、不可识别，并进入数据修复报告。
- 备份恢复必须校验对象清单、摘要和来源版本。旧备份中的证照在实例恢复开放前经过同样的重建门禁，不能通过 `putPrivateObjectAtKey` 原样恢复后直接提供。
- 所有用户下载入口只为已经通过来源门禁的系统生成对象签发短时私有 URL，并证明原始上传字节、元数据、注释和尾随内容均不会被保存或返回。

V5.2.1、V5.2.2、V5.2.4、V5.2.6 等文件大小、内容验证、用户配额和像素尺寸要求仍然适用。门禁失败时保持“待验证”，不重新引入杀毒扫描或隔离队列。

## 3. 数据模型和迁移

### 3.1 压缩后的安全信号

新增 `SecuritySignalBucket`。它按短时间桶和受控维度聚合请求，不为每次探测永久保存一行：

- `kind`：认证失败、认证限流、权限拒绝、CSRF 拒绝、已知探测路径、未知页面/API 等。
- `bucketStart`：一分钟 UTC 时间桶。
- `keyVersion`：来源、账号、路径和维度 HMAC 使用的密钥版本。
- `sourceHash`：规范化来源地址经过带域分离的 HMAC 后得到的指纹；来源无法可靠确定时为空，不用共享占位值冒充一个真实来源。
- `maskedSource`：IPv4 隐去最后一段；IPv6 只显示受控前缀；无法可靠解析时为“来源不可判定”。
- `accountHash`：规范化账号标识的 HMAC，仅用于计算不同目标数量。
- `adminUserId`、`pilotId`、`unitId`、`organizationId`：只在账号真实存在且关系已由数据库确认时写入。
- `routeClass`、`pathHash`：只保存受控路由类别和无查询参数的路径指纹。
- `dimensionKey`：服务端对规范化维度元组计算的非空 HMAC；缺失的来源、账号和路径使用不同的显式哨兵参与计算，不能依赖数据库中可空列的唯一语义。
- `outcome`、`count`、`firstSeenAt`、`lastSeenAt`、`sampleRequestId`。

每个公网请求只能产生一个规范基础信号；认证失败、路径类别和最终响应等其他特征作为该信号的受控属性，不能把同一请求分别写成多条可累计事件。新增最小化的 `SecuritySignalReceipt`，只保存内部请求键的 HMAC、最终信号桶 ID 和有限重试期限。收据与桶计数在同一事务提交，唯一请求键保证 Caddy 预检、应用终态采集、别名 handler 或重试不会重复增加计数；收据超过最大交接和重试窗口后清理。

使用数据库原子 upsert 增加 `count`。唯一约束使用 `[bucketStart, kind, keyVersion, dimensionKey]`，确保所有业务维度为空时也不会因 PostgreSQL 的 `NULL` 语义重复建桶。实现必须验证 Prisma upsert 实际命中该约束。

来源、账号、路径和维度 HMAC 从现有服务端秘密使用不同固定上下文派生，不新增管理员可编辑的密钥。相关表都保存 `keyVersion`。密钥轮换不建立跨版本身份映射；跨越版本边界时，请求并集仍可准确计算，来源数只按版本分段显示并标明“密钥轮换，跨段来源可能重复”，不得给出虚假的单一精确来源数。

### 3.2 规则结果

新增 `SecurityDetectionBucket`：

- `category`：`PUBLIC_SCAN`、`CREDENTIAL_STUFFING`、`DISTRIBUTED_LOGIN_ATTEMPT`。
- `ruleVersion`：初始为 `1`，修改阈值或算法时递增。
- `windowStart`、`windowEnd`、`firstSeenAt`、`lastSeenAt`。
- `requestCount`、`sourceCount`、`accountCount`、`pathCount`。
- 可选来源、目标和组织/单位维度，以及只含脱敏值的样例摘要。
- `dedupeKey` 唯一约束，保证任务重跑和多个 worker 并发时结果一致。

新增 `SecurityDetectionMembership`，以 `[detectionBucketId, signalBucketId]` 为唯一键，记录每个规则批次实际包含的基础信号桶。相邻或重叠窗口对同一分类和分组维度的连续命中合并为一个批次；迟到数据重算可以扩展或合并批次，但不能复制成员关系。缓存的请求、来源、账号和路径数量只能从成员关系重算，不能作为并集统计的事实来源。

同一信号桶可以属于多个分类或规则批次。区间摘要先用 `since <= signal.bucketStart < until` 裁剪成员关系，只保留裁剪后非空的批次，再取不同的 `signalBucketId`、合计 `count`，并对非空的 `[keyVersion, sourceHash]` 去重；来源不可判定的请求单列数量。分类统计也在各自分类内执行相同并集。这样，横跨摘要边界的连续批次不会带入区间外请求，同一请求命中两条规则、同一来源跨多个批次时也不会重复进入全局请求数或同版本来源数。检测详情展示整批数据时必须标明完整批次范围，与按查询区间裁剪的摘要值分开。

该表没有状态、处理人、已读时间或通知投递关系。安全审计页查询检测批次及其成员关系。

### 3.3 登录摘要时间

- `AdminUser` 增加 `lastSuccessfulLoginAt`。
- `AdminSession` 增加 `securitySummarySince` 和 `securitySummaryUntil`，在认证全部成功并创建会话时固定，摘要区间为 `[since, until)`。
- 统计以完整 UTC 分钟桶为精度。`until = floorToMinute(loginAt)`，`since = max(floorToMinute(previousLoginAt), until - 30d)`；没有历史值时取 `until - 24h`。同一分钟内再次登录得到空区间，连续登录区间首尾相接，不遗漏中间分钟。界面显示实际统计起止时间，不能暗示秒级精度。
- 创建会话时，在同一数据库事务内锁定对应 `AdminUser` 行，读取旧值、创建会话并更新 `lastSuccessfulLoginAt`；使用行锁或可重试的串行化事务，不能让两个并发登录读取同一个旧边界。
- 摘要 API 只使用当前会话中固定的两个边界，不接受客户端传入任意时间，也不在稍后的页面请求中把登录后的事件纳入本次摘要。若聚合水位尚未达到 `until`，返回“不完整”状态。

### 3.4 保留和容量

- `SecuritySignalBucket` 保留 30 天。
- `SecurityDetectionBucket`、`SecurityDetectionMembership`、脱敏样例和可关联账号/来源维度同样只保留 30 天。本轮不建立长期风险统计库。
- 清理以基础信号桶时间为准：先删除过期成员关系和信号，再从剩余成员重算批次的起止时间、数量、来源及样例，只删除已经没有成员的批次。持续超过 30 天的攻击批次标记为“已按保留期截断”，样例只能来自仍在保留期内的成员，不能因批次最后仍活跃而保留旧维度。
- `SecuritySignalReceipt` 只保留覆盖 Caddy—应用交接与最大重试所需的短周期；`AuditEvent` 是独立能力，不因风险检测表清理而改变其既有保留行为，也不得复制风险详情规避 30 天期限。
- 每个来源和全局均设置一分钟桶数量上限。超过上限时增加专门的溢出计数，不继续创建高基数字段。
- 安全审计界面显示统计是否完整、最近聚合时间和被容量保护丢弃的样例数。数据缺失时不能显示“没有攻击”。

## 4. 采集设计

### 4.1 Caddy 公网入口与覆盖边界

`forward_auth` 是请求前预检，看不到 Next.js 的最终状态。它只负责安全的路径/方法预分类和公网策略判断，不能单独作为“所有 404/405 已采集”的证据。调整 Caddy 路由顺序，使进入 CrewQual 站点处理链的所有公网请求在本地 `respond` 或 `reverse_proxy` 前先经过预检，包括外部直接探测 `/api/internal/network-access` 的请求。

预检只接收由 Caddy 覆盖的内部字段：

- 原始请求方法。`forward_auth` 自身使用 GET 时，读取 Caddy 提供并覆盖的原始方法字段，不能误把所有请求记为 GET。
- Caddy 从原始请求中提取的不含查询参数路径；预检不接收完整 URI，完整 URI 也不得写入日志、错误或数据库。
- Caddy 直接观察到的远端地址。
- 预检生成的内部请求键；允许继续代理时只把该键及受控路由类别传给应用。

这些字段只由持有 `NETWORK_ACCESS_SECRET` 的内部调用使用。Caddy 覆盖原始方法、路径、远端地址和请求键，并从预检请求移除 Cookie、Authorization 及其他无关客户端凭据。公开访问 `/api/internal/network-access` 仍返回 404，客户端自报的同名头一律不可信。

`/api/internal/network-access` 在执行现有公网访问策略检查时，使用集中维护的“路由模板 + 允许方法 + Caddy 本地处理”清单分类：

- 静态资源和已知正常路由不产生扫描信号。
- `/.env`、`/.git`、`/wp-admin`、PHP/CGI 探测、路径穿越等已知探测立即记录。
- 不匹配任何产品路由模板的页面和 API 记录为未知路径。
- 匹配路由但方法不在清单中的请求记录为无效方法。
- 动态路由使用集中维护的模板匹配，不能把随机 UUID 当作不同路由类别。

公网策略拒绝、Caddy 本地 404、已知探测、未知模板和无效方法由预检写入终态信号。进入已知应用路由的请求由应用写入终态；预检不得提前猜测其最终 404、401、403 或成功结果。两处使用同一个内部请求键和收据约束。

TLS 握手、ACME 和 Caddy 自动重定向位于该站点应用处理链之外，本轮明确排除。无需启用或持久化包含完整 URI、User-Agent 等内容的通用 Caddy 原始访问日志。Caddy 自身的 5xx 由运维健康指标反映，并使统计完整性降级，不能被归类成扫描。

采集失败不得改变原有公网允许/拒绝结论。公网访问策略检查失败仍按现有规则失败关闭；统计写入失败则记录内部健康状态，不能让安全统计功能拖垮所有请求。

新增的路由分类清单与仓库路由清单测试绑定。增加新页面或 API 时，如果没有分类，测试必须失败。

### 4.2 应用终态、认证和拒绝事件

在源入口采集，兼容别名继续复用同一 handler，避免重复计数：

- 管理员登录、FIDO 选项和密码恢复。
- 成员密码登录、短信链接请求和链接兑换。
- 管理员和成员成功登录只作为与已命中扫描/撞库来源关联的基础证据，不因来源变化单独生成检测结果。
- 管理接口的认证失败、权限拒绝和 CSRF 拒绝。
- 共享错误/响应出口中的动态路由资源不存在；例如路径模板有效但对象 ID 不存在的 404，只按受控路由类别和参数指纹记录。
- 页面 not-found、API catch-all 和共享 `jsonError`/守卫结果；Caddy 已完成终态记录的请求由收据阻止应用层再次累计。

未知账号和已知账号保持同样的外部响应。信号写入发生在统一响应决定之后，不得改变响应内容或明显扩大时序差异。

现有 `RateLimitBucket.key` 中的原始地址和账号也改为 HMAC 指纹，避免一边宣称脱敏、一边在限流表保存原值。迁移不转换旧键；旧桶按窗口自然失效并由清理任务删除。

## 5. 检测规则 v1

| 分类           | 初始规则                                                         | 窗口                     |
| -------------- | ---------------------------------------------------------------- | ------------------------ |
| 已知公网探测   | 同一来源请求已知恶意探测路径；同一时间段合并为一组               | 5 分钟                   |
| 路径枚举扫描   | 同一来源至少 20 次未知或受拒绝请求，且涉及至少 10 个不同路径指纹 | 5 分钟                   |
| 撞库           | 同一来源至少 10 次登录失败，涉及至少 5 个账号指纹                | 10 分钟                  |
| 分布式登录尝试 | 同一账号指纹至少 10 次失败，来自至少 5 个来源指纹                | 10 分钟                  |
| 组合风险       | 已命中上述规则的来源随后成功登录                                 | 沿用原规则窗口并单独标记 |

阈值属于版本化产品常量，第一版不增加设置项。安全审计页显示规则说明及版本。调整阈值前先检查实际误报、漏报和容量数据。

规则窗口均为半开区间，并在每个 UTC 分钟边界 `T` 评估 `[T - window, T)`。重叠窗口用于避免边界漏报；同一分类和分组维度的连续命中合并为一个检测批次，成员关系负责消除窗口和规则重叠造成的请求/来源重复。分类请求数可以彼此重叠，界面同时显示全局并集，不能相加分类数。

聚合任务每分钟由 pg-boss 调度：

- 使用水位记录已完成的时间桶。
- 迟到数据在有限回看窗口内重算。
- 相同规则、窗口和维度只能生成一个结果；相邻结果的批次合并及成员写入必须幂等。
- worker 停止或落后时，界面显示“统计延迟”，不回退为零风险结论。

## 6. API 和界面

### 6.1 API

新增只读接口：

- `GET /api/admin/security/summary`：返回当前登录会话对应时间段的全局摘要。
- `GET /api/admin/security/trends?range=24h|7d|30d`：返回分类趋势、批次、请求和来源统计。
- `GET /api/admin/security/detections`：分页返回检测批次和脱敏证据摘要。

三者均要求有效管理员会话和 `audit.read`。服务端根据当前角色处理账号标识：

- 超级管理员可查看所有已确认账号。
- 普通管理员只查看查询时数据库仍确认属于本单位的完整账号；事件发生时保存的历史单位只用于统计，不能作为详情授权依据。账号调动、删除、关系缺失或冲突时默认返回脱敏标识。
- 未知账号永远不返回原始输入。

接口不提供确认、处理、删除或“设为已知来源”操作。

### 6.2 安全审计界面

在现有“安全与审计”区域增加：

- 当前数据状态和最近聚合时间。
- 三个摘要值：疑似攻击批次、相关请求、来源。
- 按扫描、撞库、分布式尝试分类的趋势图。
- 检测批次列表，显示时间、分类、规则依据、脱敏来源及请求/账号/路径数量。
- 24 小时、7 天、30 天切换和分页。

图表必须同时提供文本和表格信息，不能只靠颜色表达分类。空状态、统计延迟、来源不可判定和容量溢出分别展示。

### 6.3 登录后提示

管理员外壳在成功建立会话后调用摘要 API：

- 非零：显示批次数、请求数和来源数。
- 为零且统计完整：显示“自上次登录以来未检测到疑似恶意扫描或撞库”。
- 数据延迟或采集异常：显示“安全统计暂不完整”，不能显示零结果。

前端使用当前会话 ID 在浏览器本地记录本次会话是否已展示，只用于避免页面跳转重复弹出，不上传为已读状态。

## 7. 主体/客体访问控制实施

### 7.1 写出可信规则

新增 `docs/security/subject-object-access-control.md`，逐项记录：

- 主体如何从有效会话和数据库关系解析。
- 客体的所有者、组织和单位从哪个可信关系派生。
- 每种操作需要的权限及范围。
- 哪些字段只能由服务端生成，哪些角色可以变更归属。
- 缺少归属、双重归属冲突和父子关系冲突时一律拒绝。
- 签名 URL 在签发时完成鉴权，最长保留现有 5 分钟持有窗口；撤销会话不会使已经签发的 URL 立即失效。

同时建立机器可检查的路由—主体—客体—动作清单。新增 API 若没有登记，路由清单测试失败。

### 7.2 统一主体上下文

- 管理员每次请求继续重新读取角色、权限、组织和单位。
- 超级管理员范围统一为全局；新旧入口不得再出现一个全局、一个受 `organizationId` 限制的差异。
- 普通管理员必须有单位，且同时通过权限与单位范围检查。
- 成员认证结果扩展为服务端解析的规范身份，包含成员、人员、组织和单位关系；路由不从请求体接受这些归属。
- 新旧 `member`/`pilot` 别名使用同一个主体解析和 repository 查询。

### 7.3 统一客体范围

- 集中现有 `pilotUnitWhere`、`memberScopeWhere` 及相关 helper，避免各路由自行拼接宽松条件。
- `pilotId` 与 `personId` 同时存在时必须指向同一人员；只有一个字段时通过可信迁移关系解析；两者都没有时拒绝访问并进入数据修复清单。
- 查询父资源后再读取证照、识别结果或子记录时，验证子资源归属与父资源一致。
- 列表、详情、计数、导出、批量修改和删除使用相同范围，不允许“详情安全、聚合泄露”。
- 越权和不存在统一返回安全的 404，不生成签名 URL，不写入业务数据，也不投递后台任务。
- 后台识别、图片优化和清理任务只携带内部 ID；执行时重新读取资源及归属，不信任任意对象存储 key。

### 7.4 入口范围

至少覆盖：

- `member` 与 `pilot` 两套成员 API。
- `admin/members` 与 `admin/pilots` 两套管理入口。
- 人员、资质、更新申请、证照图片、识别结果、通知、升级计划、日历和导出。
- 设置、审计、管理员账号、会话和备份配置。
- 对象签名 URL、队列任务、批量导入和历史兼容入口。

只在矩阵发现差异时修改业务代码或数据库约束，不预先增加无实际用途的标签列。
