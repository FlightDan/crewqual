# CrewQual 产品安全差距审计

审计日期：2026-09-07。代码基线：`782a1d18c74ec26e4c1cae4a65d9e52c1b86c036`，审计开始时工作树干净。

本报告分别列出 ASVS 5.0.0 L2、L3，以及 GB/T 22239—2019 二级、三级的**产品工程差距**。范围仅包括产品代码、API、界面、随附工具与产品安全设计证据；按委托要求，不列部署方负责或不适用的条目。

这是代码与配置审查、有限隔离单测形成的差距报告，不是完整动态验收、渗透测试或正式等保测评。已对 ASVS 官方 345 条要求做范围筛选，并对相关产品路径重点检查；筛选数量不代表逐条验证通过。未修改产品实现，未向实际外部集成发送数据。

状态含义：**明确差距**有当前实现作为直接证据；**待验证**表示产品路径或证明仍需检查，不能算已确认漏洞。P1/P2/P3 是本次建议处理顺序，不是 CVSS 分数，也不表示每项都有已验证的利用路径。

## 7. 处理顺序与跨标准差异

1. 先处理 A2-07 的完整重新认证、A2-01/A2-02 的账号与成员认证、A2-05 的空闲超时；其中成员认证也直接影响 G3-01。
2. 补齐安全事件记录与独立审计权限，处理 A2-14/A2-15、G2-01/G2-02；再补 L3 敏感读取审计。
3. 修正 TOTP 生成与有效窗口、Cookie/CSP、密钥轮换、文件扫描和用户配额，并补对应负向用例。
4. 对计划承诺 L3 的产品增加硬件抗钓鱼认证、用户完成的密码恢复、高敏操作验证、上下文风险和安全标记能力。

不要把两套标准机械合并。例如 ASVS **V6.2.10** 明确不要求周期性更换密码，而 GB/T 22239—2019 **7.1.4.1 a)、8.1.4.1 a)** 涉及鉴别信息定期更换。后续应明确目标口径与采用方式，不能通过统一强制密码过期就宣称同时满足两者。本报告不把部署方执行周期更换的情况列为产品缺口。
