# 证照来源重建与恢复门禁

`storageEncodingVersion = 1` 且 `sanitizedAt` 有效表示当前对象由服务端从解码像素重新生成。版本为 0、未知版本、缺少时间或对象摘要/大小/类型冲突时，不签发证照 URL，也不向识别服务发送图像。图库 AVIF 优化只接受已通过来源门禁的对象。

## 现有对象

先部署新增字段和读取门禁，再在受控维护窗口执行：

```sh
SERVICE_MODE=remote corepack pnpm exec tsx scripts/reconcile-evidence-sources.ts
```

命令使用当前数据库及对象存储配置，不从命令行接受任意对象 key。每次遍历全部证照：验证数据库摘要、实际字节和所有者；已有可信来源还会复核对象存储中的大小、类型和摘要元数据，其余 JPEG/AVIF 完整解码并生成新 JPEG。新对象写入确定性 key，数据库以原 key、摘要、更新时间和来源版本作条件更新，成功后才切换。旧对象删除记录与切换同事务提交，删除可在下次运行重试。

重跑会复用已完成状态，并继续清理已退役对象。并发变化不会被覆盖，需再运行复核。无法解码、对象缺失、摘要或归属冲突的条目保留为不可读，并在 JSON 报告中只输出内部记录 ID 和受控原因。报告含 `inspected`、`rebuilt`、`verified`、`conflicts`、`failures`；出现冲突或失败时退出码为 1。退出码为 0 仅表示本次数据检查完成，不代表其他安全条款已通过。

此命令会删除成功重建后已退役的旧对象；运行前应确保产品备份可恢复。失败的旧对象继续阻止读取，需要按报告修复，不能手工把版本改为 1 绕过重建。

## 备份恢复

仍使用现有隔离恢复命令。数据库 dump 恢复后，所有证照来源标记先清零；数据库恢复结果会显示 `evidenceStatus: awaiting_gallery_rebuild`。图库恢复逐个验证归档摘要，在内存中完整重建 JPEG/AVIF 为新 JPEG，然后写入隔离目标存储。未知来源版本被拒绝，旧版本没有来源标记的备份可以走重建流程。

全部对象验证及提升完成后，恢复程序核对数据库与备份原始 key/摘要/类型，再在数据库事务内发布新的摘要、大小、尺寸、类型及来源版本。缺少正在使用的对象、数据库与图库备份不匹配或中途失败时，不开放实例。孤儿记录未包含在图库备份中时仍保持不可读；旧库恢复到当前版本的其他数据库迁移门禁仍须完成。

## 验收证据

文件入口机器清单见 `file-entry-inventory.json`，测试会检查新增二进制读取入口、对象存储调用方和直接 S3 读写位置。CSV 导入只解析结构化数据，不保存可下载原文件；存储健康检查和发布验收使用系统生成的探针。

单元测试覆盖 JPEG 元数据/注释/尾随内容剥离、旧 AVIF 重建、对象元数据冲突拒绝、来源冲突拒绝、并发切换失败、重跑与退役对象清理、恢复清单不匹配及来源标记清零。旧表执行恢复清零后再应用当前迁移的真实 PostgreSQL 回归已经通过。实际发布仍须在隔离对象存储完成全部现有对象的重建报告、并发/中断续跑和整套备份恢复验证。未完成这些实际证据前，ASVS V5.4.3 的项目特定“不适用”判断保持待验证。
