# 架构说明

[English](../en/architecture.md) · [文档目录](README.md)

CrewQual 使用 Next.js App Router 和 React 构建界面与 HTTP API，使用 Prisma 访问 PostgreSQL。凭证文件保存在 S3 兼容对象存储中，后台任务由独立的 Node.js Worker 执行。

## 部署进程

| 服务                | 职责                                                          |
| ------------------- | ------------------------------------------------------------- |
| Caddy               | 接收浏览器请求，按部署模式处理 HTTP 或 TLS，并代理到 Web      |
| Web                 | 页面、身份验证、权限校验与业务 API                            |
| PostgreSQL          | 业务记录、会话、审计、任务队列及 Worker 心跳                  |
| Worker              | 消费 pg-boss 队列，执行识别、通知、提醒、清理、图像优化及备份 |
| 对象存储            | 保存私有凭证文件；安装方式和配置决定使用内置或外部存储        |
| migrate / bootstrap | 启动前执行数据库迁移和初始化的一次性任务                      |
| ops                 | 按需执行运维命令的运行时容器                                  |

[Dockerfile](../../Dockerfile)分别构建 Web 和数据运行时。Web 使用 Next.js standalone 输出；Worker、迁移和运维容器使用数据运行时，其中包含 PostgreSQL 客户端和备份所需工具。

## 一次资质提交的数据流

成员在界面中上传凭证、核对识别结果并提交字段。服务端验证身份、资源归属和资质规则，保存更新请求及其规则快照。识别任务由 Worker 调用配置的服务，服务端将提取结果与提交字段、规则快照进行比较。

AI 核验结果是审核依据之一。授权管理员作出审核决定后，系统按决定更新申请状态和生效记录，并记录审计信息。通知由后台任务处理。识别、人工审核和通知是不同状态，通知失败不等于审核失败。

可从 [成员提交 API](../../src/app/api/pilot/submissions/route.ts)、[核验逻辑](../../src/server/qualification-verification.ts)和 [Worker 处理器](../../src/server/worker-handlers.ts)追踪实现。

## 数据与权限边界

应用和 Worker 通过 `DATABASE_URL` 使用运行时账号。迁移通过 `DIRECT_URL` 使用拥有迁移权限的账号。pg-boss 的结构由迁移过程创建，长驻进程不自行执行队列结构迁移。完整初始化顺序见[开发指南](development.md)。

权限由服务端验证；界面隐藏按钮只是显示逻辑。外部连接受部署方配置的主机与网段限制，应用管理员不能通过设置界面扩大这层边界。对象存储与远程备份的额外要求见[配置参考](configuration.md)。

备份恢复需要同时考虑数据库、凭证对象和加密设置所用密钥。流程与限制见[运维指南](operations.md)。

## 代码目录

| 路径             | 内容                                       |
| ---------------- | ------------------------------------------ |
| `src/app`        | 页面与 API 路由                            |
| `src/components` | 管理端、成员端、首次设置及通用组件         |
| `src/services`   | 前端服务接口、模拟与真实实现、客户端状态   |
| `src/server`     | 权限、数据库访问、规则执行、存储与外部服务 |
| `src/lib`        | 共享校验、日期处理与语言资源               |
| `src/types`      | 服务和业务类型                             |
| `src/worker`     | 后台任务入口与生命周期                     |
| `src/mocks`      | 开发和测试数据                             |
| `prisma`         | 数据模型、迁移和种子脚本                   |
| `scripts`        | 初始化、恢复、管理员维护和发布工具         |
| `e2e`            | 浏览器与真实后端端到端测试                 |

仓库中部分路径和类型保留 `pilot` 命名。查找成员功能时，需要同时搜索成员术语和这些路径。

## 中英文支持

应用使用 `zh-CN` 和 `en-US` 两种语言标识，默认中文。语言解析优先使用 `crewqual_locale` Cookie，再读取浏览器的 `Accept-Language`。界面资源与业务字段的翻译辅助函数放在 `src/lib`。

文档使用 `zh-CN` 和 `en` 目录；`en` 是文档路径，不是应用的语言标识。翻译页面时保留命令、环境变量、API 路径和状态代码，避免读者复制后无法使用。

## 模拟与真实服务

开发环境默认采用模拟模式；真实服务需要显式配置。生产界面的模式选择固定为真实服务，生产配置也会校验相关约束。修改某项功能时，应核对模拟和真实服务的契约，避免预览可用而真实接口不支持。入口见 [服务模式](../../src/lib/service-mode.ts)、[应用服务](../../src/services/application-services.ts)和 [服务端配置](../../src/server/config.ts)。
